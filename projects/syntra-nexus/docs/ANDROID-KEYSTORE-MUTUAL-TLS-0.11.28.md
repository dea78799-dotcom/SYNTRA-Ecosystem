# Android Keystore mutual-TLS loopback verification — 0.11.28-dev

## Scope

This milestone adds an Android instrumentation test that attempts a real mutual-TLS handshake on the emulator loopback interface. The server and client each use a separate, temporary Android Keystore alias generated by the test. The production installation identity is never read, replaced or deleted. Neither private key is exported.

## Implementation

- `AndroidKeystoreX509KeyManager` accepts an explicit alias while retaining the production installation alias as its default.
- The test creates two independent P-256 key pairs directly in Android Keystore under test-only aliases.
- Both contexts are created by `NexusTlsContextFactory`, each pinned to the other test identity's fingerprint.
- The client context uses the test-only Keystore key manager and pins the server's installation certificate.
- The test configures TLS 1.2/1.3 and requires a client certificate on the server socket.
- The successful case performs a one-byte echo only after the TLS handshake completes.
- The negative case gives the server a different pinned fingerprint and expects the client's certificate to be rejected.
- Both test aliases are deleted before and after each test. The production identity alias is untouched.

## Security boundary

All sockets bind to `InetAddress.getLoopbackAddress()` and use an ephemeral port. The test does not use Wi-Fi, LAN discovery, an external host or another physical device. The temporary client key remains in Android Keystore and is not exported or stored in repository assets.

This test does not implement a production listener, QR token redemption, pairing state transitions, remote capability requests, file transfer, screen capture or remote control. A successful loopback test would validate TLS integration on the tested emulator only; it would not prove interoperability across OEM devices or establish a user-approved pairing.

## Verification status

The source is committed for Android emulator CI. It must not be described as passed until the connected Android instrumentation test reports success. The debug APK and JVM unit-test jobs must also pass before the build is considered verified.
